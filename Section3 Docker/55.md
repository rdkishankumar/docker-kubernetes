## Question 1: Why don't changes to server-side JavaScript files reflect immediately in a running Docker container with bind mounts, even though HTML file changes do?

### Answer

**The Root Cause:**

Node.js loads and executes JavaScript files **once at startup**. When the Node.js server starts, it reads `server.js`, compiles it, and keeps it in memory. The running process does not monitor the file system for changes — it continues using the in-memory version.

**Why HTML Works Immediately:**

HTML files (and other static assets) are typically served fresh on each request. When a browser requests an HTML file, the server reads it from disk at that moment. Since the bind mount provides live access to your host files, changes are reflected on the next request.

**Why Server JS Doesn't:**

The server code defines the application's behavior. Changing `server.js` on disk has no effect on the already-running Node.js process. The process would need to be restarted to re-read and re-execute the changed file.

**The Implication:**

With bind mounts alone, you still need to restart the container (or the Node process) to pick up server-side code changes. This is better than rebuilding the image, but still interrupts your development flow.

### Practical Guide

```bash
docker build -t feedback-node .

docker run -d -p 3000:80 \
  -v "$(pwd):/app" \
  -v /app/node_modules \
  --rm \
  --name feedback-app feedback-node

# ============================================
# DEMONSTRATE: HTML changes work immediately
# ============================================

echo "=== Testing HTML Changes ==="

# Check current HTML
curl -s http://localhost:3000 | grep -o "<h1>.*</h1>" | head -1

# Modify HTML on host
sed -i.bak 's/<h1>/<h1>MODIFIED: /' feedback.html

# Change is immediate - no restart needed
curl -s http://localhost:3000 | grep -o "<h1>.*</h1>" | head -1
# MODIFIED: ... ✓

# Restore
mv feedback.html.bak feedback.html

# ============================================
# DEMONSTRATE: JS changes require restart
# ============================================

echo "=== Testing JavaScript Changes ==="

# Add a console.log to server.js
sed -i.bak '/app.post/a\  console.log("TEST LOG - If you see this, changes were picked up");' server.js

# Trigger the code path
curl -X POST -d "title=jstest&text=Testing JS changes" http://localhost:3000/submit

# Check logs - the new log statement is NOT there
docker logs feedback-app 2>&1 | grep "TEST LOG"
# (no output - change not picked up) ✗

# We must restart the container
docker stop feedback-app

docker run -d -p 3000:80 \
  -v "$(pwd):/app" \
  -v /app/node_modules \
  --rm \
  --name feedback-app feedback-node

# Now trigger again
curl -X POST -d "title=jstest2&text=After restart" http://localhost:3000/submit

# Check logs - NOW it appears
docker logs feedback-app 2>&1 | grep "TEST LOG"
# TEST LOG - If you see this, changes were picked up ✓

# Restore
mv server.js.bak server.js

docker stop feedback-app
```

## Question 2: What is nodemon, and how does it solve the server restart problem in Docker development?

### Answer

**What is nodemon:**

nodemon is a Node.js development utility that **monitors your source files** for changes and **automatically restarts** the Node.js process when changes are detected. It wraps around the standard `node` command but adds file watching capabilities.

**How it solves the problem:**

1. Instead of running `node server.js`, you run `nodemon server.js`
2. nodemon starts the Node.js server normally
3. nodemon also watches the file system for changes
4. When a `.js` file changes, nodemon automatically:
   - Stops the current Node.js process
   - Restarts it with the updated code
5. This happens within the container — no container restart needed

**Key Benefits:**
- No manual container stops/starts for server code changes
- Sub-second restart times
- Works seamlessly with Docker bind mounts
- Development workflow matches non-Docker development

### Practical Guide

```bash
# ============================================
# SETUP: Add nodemon to the project
# ============================================

# Update package.json with nodemon as a dev dependency
cat > package.json << 'EOF'
{
  "name": "feedback-app",
  "version": "1.0.0",
  "main": "server.js",
  "scripts": {
    "start": "nodemon server.js"
  },
  "dependencies": {
    "express": "^4.18.2",
    "body-parser": "^1.20.2"
  },
  "devDependencies": {
    "nodemon": "^2.0.4"
  }
}
EOF

# Update Dockerfile to use npm start (which runs nodemon)
cat > Dockerfile << 'EOF'
FROM node:14
WORKDIR /app
COPY package.json .
RUN npm install
COPY . .
EXPOSE 80
CMD ["npm", "start"]
EOF

# Build the updated image
docker build -t feedback-node .

# ============================================
# RUN: Container with nodemon
# ============================================

docker run -d -p 3000:80 \
  -v "$(pwd):/app" \
  -v /app/node_modules \
  --rm \
  --name feedback-app feedback-node

# Check that nodemon is running
docker logs feedback-app
# [nodemon] 2.0.4
# [nodemon] to restart at any time, enter `rs`
# [nodemon] watching path(s): *.*
# [nodemon] watching extensions: js,mjs,json
# [nodemon] starting `node server.js`
# Listening on port 80

# ============================================
# TEST: Automatic restart on code change
# ============================================

# Make a change to server.js
echo '
// Added during development
console.log("Hot reload test - timestamp:", Date.now());
' >> server.js

# Wait a moment for nodemon to detect the change
sleep 2

# Check logs - nodemon should have restarted
docker logs feedback-app --tail 10
# [nodemon] restarting due to changes...
# [nodemon] starting `node server.js`
# Hot reload test - timestamp: 1234567890
# Listening on port 80 ✓

# Trigger the app to verify it works
curl http://localhost:3000
# Success! ✓

# ============================================
# VERIFY: Multiple rapid changes
# ============================================

# Make several quick edits
for i in 1 2 3; do
  sed -i "s/timestamp:.*/timestamp: $i\");/" server.js
  sleep 1
done

# nodemon handles all of them
docker logs feedback-app --tail 15 | grep -E "(restarting|timestamp)"
# [nodemon] restarting due to changes...
# Hot reload test - timestamp: 1
# [nodemon] restarting due to changes...
# Hot reload test - timestamp: 2
# [nodemon] restarting due to changes...
# Hot reload test - timestamp: 3

# Clean up test changes
git checkout server.js 2>/dev/null || true

docker stop feedback-app
```

```json
    "nodemon": "^2.0.4"
```

## Question 4: What special considerations exist for Windows users with WSL2 when using Docker bind mounts and file watching tools like nodemon?

### Answer

**The Problem:**

When using Docker Desktop with WSL2 on Windows, file change events may not propagate correctly from the Windows file system to the Docker container. This causes nodemon (and similar tools) to not detect file changes, breaking the hot reload functionality.

**Root Cause:**

WSL2 runs a real Linux kernel in a lightweight VM. When you store files on the Windows file system (e.g., `C:\Users\...`) and access them from WSL2/Docker, the file system events (inotify) don't cross the boundary properly. The Windows file system and Linux file system are separate, and change notifications don't translate well between them.

**The Solution:**

Store your project files directly in the **Linux file system** within WSL2, not on the Windows file system. The Linux file system is accessible at:
- From WSL2 terminal: `/home/username/projects/`
- From Windows Explorer: `\\wsl$\Ubuntu\home\username\projects\`

**How to Access:**

1. Open Windows Explorer
2. Type `\\wsl$` in the address bar
3. Navigate to your Linux distribution (e.g., Ubuntu)
4. Store projects in `/home/your-username/`

### Practical Guide

```bash
# ============================================
# CHECK: Are you affected by this issue?
# ============================================

# If you're on Windows with WSL2 and file changes
# don't trigger nodemon restarts, you likely have
# your project on the Windows file system.

# Check your current project location:
pwd
# If it shows: /mnt/c/Users/... → PROBLEM (Windows file system)
# If it shows: /home/...        → GOOD (Linux file system)

# ============================================
# SOLUTION: Move project to Linux file system
# ============================================

# 1. Create a projects directory in Linux home
mkdir -p ~/projects

# 2. Copy your project from Windows to Linux
cp -r /mnt/c/Users/YourName/projects/feedback-app ~/projects/

# 3. Navigate to the Linux location
cd ~/projects/feedback-app

# 4. Run Docker from here
docker run -d -p 3000:80 \
  -v "$(pwd):/app" \
  -v /app/node_modules \
  --rm \
  --name feedback-app feedback-node

# 5. Verify nodemon works
echo 'console.log("WSL2 FIX TEST");' >> server.js
sleep 2
docker logs feedback-app --tail 5
# Should show: [nodemon] restarting due to changes...

# ============================================
# ACCESSING LINUX FILES FROM WINDOWS
# ============================================

# From Windows Explorer, navigate to:
# \\wsl$\Ubuntu\home\your-username\projects\feedback-app

# You can:
# - Open files in VS Code (which has great WSL2 support)
# - Edit directly from Windows
# - Changes will now be detected by nodemon

# ============================================
# VS CODE INTEGRATION
# ============================================

# VS Code has excellent WSL2 support:
# 1. Install "Remote - WSL" extension in VS Code
# 2. Open WSL2 terminal
# 3. Navigate to your project
# 4. Run: code .
# This opens VS Code connected to WSL2

# ============================================
# ALTERNATIVE: Polling mode (slower but works anywhere)
# ============================================

# If you MUST use the Windows file system, enable polling:
# In package.json:
# "scripts": {
#   "start": "nodemon --legacy-watch server.js"
# }

# --legacy-watch uses polling instead of inotify
# It's slower and uses more CPU, but works across file systems

# Or set environment variable:
docker run -d -p 3000:80 \
  -v "$(pwd):/app" \
  -v /app/node_modules \
  -e CHOKIDAR_USEPOLLING=true \
  --rm \
  --name feedback-app feedback-node
```

## Question 5: How do you use Docker logs to debug and verify that nodemon is working correctly?

### Answer

**Docker logs command:**

```bash
docker logs <container-name>           # Show all logs
docker logs --tail 20 <container-name> # Last 20 lines
docker logs -f <container-name>        # Follow (stream) logs in real-time
```

**What to look for in nodemon output:**

1. **Startup message**: Confirms nodemon is running
   ```
   [nodemon] 2.0.4
   [nodemon] watching path(s): *.*
   [nodemon] starting `node server.js`
   ```

2. **Restart message**: Confirms file changes are detected
   ```
   [nodemon] restarting due to changes...
   [nodemon] starting `node server.js`
   ```

3. **Application output**: Your console.log statements
   ```
   Listening on port 80
   ```

4. **Errors**: Any crashes or issues
   ```
   [nodemon] app crashed - waiting for file changes before starting...
   ```

### Practical Guide

## Question 6: Compare the development workflow before and after implementing nodemon with bind mounts.

### Answer

| Aspect | Without Nodemon | With Nodemon |
|--------|-----------------|--------------|
| **HTML/CSS changes** | Immediate (bind mount) | Immediate (bind mount) |
| **Server code changes** | Manual restart required | Automatic restart |
| **Time per iteration** | 5-10 seconds | <1 second |
| **Developer action** | Stop → Start container | Just save the file |
| **Feedback loop** | Interrupted | Continuous |
| **Container lifecycle** | Frequently stopped/started | Stays running |
| **Mental overhead** | High (remember to restart) | Low (automatic) |

### Practical Guide

```bash
# ============================================
# WORKFLOW COMPARISON: WITHOUT NODEMON
# ============================================

# Build image WITHOUT nodemon
cat > Dockerfile.no-nodemon << 'EOF'
FROM node:14
WORKDIR /app
COPY package.json .
RUN npm install
COPY . .
EXPOSE 80
CMD ["node", "server.js"]
EOF

docker build -t feedback-node:no-nodemon -f Dockerfile.no-nodemon .

echo "=== WITHOUT NODEMON: Each change cycle ==="

# Start container
docker run -d -p 3000:80 \
  -v "$(pwd):/app" \
  -v /app/node_modules \
  --rm \
  --name no-nodemon feedback-node:no-nodemon

# Make a change
echo 'console.log("Change 1");' >> server.js

# Change NOT detected - must manually restart
docker stop no-nodemon
docker run -d -p 3000:80 \
  -v "$(pwd):/app" \
```
